# Repo Radar

[English](./README.md)

Repo Radar 可以把本地代码仓库转换成一份简洁、可交互的项目驾驶舱。它只在你的电脑上扫描，最终生成一个独立的 HTML 文件，不会向外发送任何数据。

它适合用来快速了解陌生仓库：这里有什么、项目怎么运行、当前改了什么，以及下一步最值得先处理什么。

## 主要功能

- 文件、目录、大小、技术栈和语言构成概览
- 自动识别启动、测试、构建、代码检查和类型检查命令
- README、测试、许可证、持续集成和 Git 工作区信号
- 最近提交、当前变更、大文件和 TODO 类代码标记
- 给出按优先级排列的下一步，而不是塞一个看起来很科学的装饰性评分
- 报告完全离线，支持明暗主题和中英文一键切换
- 不需要安装依赖、包管理器、账号或服务器，也不会发起网络请求

## 运行要求

- Windows
- Windows PowerShell 5.1 或 PowerShell 7
- 用于查看报告的现代浏览器
- Git 为可选依赖；没有 Git 时，不会显示分支、提交和工作区变更信息

## 快速开始

克隆仓库并进入项目目录：

```powershell
git clone https://github.com/HuangWeiTao-beep/repo-radar.git
cd repo-radar
```

扫描一个项目并自动打开报告：

```powershell
.\repo-radar.ps1 C:\你的项目路径 -Open
```

默认会在执行命令的目录中生成 `repo-radar-report.html`。

### 命令提示符与拖放运行

也可以使用 `repo-radar.cmd`：

```bat
repo-radar.cmd C:\你的项目路径
```

不传参数时，`.cmd` 会扫描当前工作目录。你也可以把项目文件夹直接拖到它上面，扫描完成后报告会自动打开。

## 参数说明

| 参数 | 作用 | 默认值 |
| --- | --- | --- |
| `-Path` | 要扫描的项目目录，也可以直接作为第一个位置参数传入 | 当前目录 |
| `-Output` | 生成的 HTML 报告保存位置 | 执行命令目录下的 `repo-radar-report.html` |
| `-MaxFiles` | 最大扫描文件数量，允许范围为 100–100,000 | `20000` |
| `-Open` | 扫描成功后自动打开报告 | 关闭 |

示例：

```powershell
# 扫描当前目录
.\repo-radar.ps1 .

# 指定报告保存位置
.\repo-radar.ps1 C:\work\my-app -Output C:\reports\my-app.html

# 扫描大型仓库并打开报告
.\repo-radar.ps1 C:\work\large-repo -MaxFiles 50000 -Open
```

相对的 `-Output` 路径以执行命令时所在的目录为基准，而不是以被扫描项目为基准。目标目录不存在时会自动创建。

## 各项数字是什么意思

Repo Radar 同时使用文件系统数据和 Git 数据，它们衡量的是不同东西。

| 指标 | 含义 |
| --- | --- |
| 文件 | 扫描范围内磁盘上实际存在的文件，包括 `.gitignore` 这类隐藏文件 |
| 目录 | 扫描器实际进入的目录；项目根目录也算一个 |
| 源码大小 | 所有已扫描文件的合计大小 |
| 变更 | `git status --short` 返回的当前工作区项目，不是累计修改次数或提交次数 |
| 标记 | 匹配到的 TODO、FIXME、HACK 和 XXX 注释行 |
| 最近活动 | 最近最多五次 Git 提交 |

如果生成的报告位于被扫描项目内部，本次报告文件本身不会计入统计。否则扫描器会读取自己上一次的输出，数字会逐次膨胀，最后变成一套很有递归精神但毫无用处的俄罗斯套娃。

Git 历史不会影响文件和目录数量。一个仓库可以有几百次提交，但当前只有九个文件。同样，“3 个变更”表示目前有三个工作区项目等待提交，不代表仓库只有三次提交。

## 扫描范围与忽略规则

Repo Radar 直接扫描文件系统，而不是只读取 Git 已跟踪文件。因此，被 `.gitignore` 忽略的文件仍可能被扫描，除非它位于默认排除目录内，或者正好是本次生成的报告。

默认跳过以下 18 类目录：

```text
.git          node_modules   dist          build
.next         .nuxt          out           vendor
coverage      .venv          venv          target
bin           obj            __pycache__   .idea
.gradle       .cache
```

目录链接和重解析点也会被跳过，避免发生循环扫描。报告页脚会分别显示本次实际遇到并跳过的目录，以及完整的默认忽略规则。

扫描达到 `-MaxFiles` 上限后会停止，并在报告中显示覆盖范围警告。此时的统计与建议只代表已经扫描到的部分。

TODO 类内容检查只处理支持的文本文件，并且文件不得大于 1 MB。报告最多保留前 40 条匹配代码行，但顶部显示的标记总数可能更大。

## 报告会检测什么

- 常见项目清单文件和技术栈标记
- 仓库明确声明的可信命令，例如 `package.json` 中的脚本
- README、测试、许可证和常见 CI 工作流文件
- Git 分支、当前状态和最近提交标题
- 超过 5 MB 的文件
- `.env`、私钥和证书等疑似敏感文件名
- TODO、FIXME、HACK 和 XXX 注释

这些结果来自启发式检测。Repo Radar 不会执行项目命令、安装依赖，也不会在缺乏仓库证据时现场编造一条可能把项目跑炸的命令。

## 隐私与安全

整个扫描过程都在本机完成，生成的报告可以离线使用，不会上传源代码。

HTML 报告可能包含：

- 项目路径和文件路径
- Git 提交标题及工作区文件名
- TODO 类标记所在的代码行
- 疑似敏感文件的名称

分享报告前，请像检查源代码一样检查它。Repo Radar 只报告疑似敏感文件的名称，不会把其中的密钥内容写入报告。它也不是密钥扫描器、漏洞扫描器或正式安全审计工具。

## 常见问题

### PowerShell 提示禁止运行脚本

可以使用仅对当前进程生效的执行策略绕过：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\repo-radar.ps1 -Path C:\你的项目路径 -Open
```

这不会永久修改电脑的执行策略。使用 `repo-radar.cmd` 时也会自动采用相同方式。

### 报告内容没有更新

重新运行扫描，然后在 HTML 页面中按 `Ctrl+R` 刷新。报告是一份生成时的快照，不会持续监控仓库。

### 没有显示 Git 信息

确认电脑已经安装 Git，并且扫描目录位于 Git 工作区内：

```powershell
git --version
git -C C:\你的项目路径 status
```

### 没有识别出项目命令

如果仓库不存在受支持的项目清单或没有声明相关脚本，这是正常结果。Repo Radar 宁可留空，也不编造一条可能破坏项目的命令。

## 开发与验证

在 Repo Radar 仓库根目录运行冒烟测试：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\smoke.ps1
```

测试会验证报告生成、Git 中文输出、UTC 偏移格式、TODO 检测、目录忽略规则、达到扫描上限时正确排除旧报告，以及扫描测试脚本时不会产生假 TODO 的回归场景。
